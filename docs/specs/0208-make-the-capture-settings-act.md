# SPEC: feat(settings): make the capture settings act

## Problem

The Developer asked on 2026-10-26 for "100% de fidelidade ao mock" ("100% fidelity to the mock"). PNG 23 draws three switches under "Câmera e análise" as live controls:

- Guia de enquadramento, on;
- Salvar fotos na galeria, off;
- Registrar localização, off.

SPEC 0204 left all three disabled, at 38 % opacity, because nothing stood behind them. As long as nothing acts on them, the screen cannot match the mock without showing a switch that lies.

## Design Decision

- **Preferences.** Three stored booleans, read before the first frame like Vibração (SPEC 0184), each behind a `Notifier` in `lib/providers/capture_preferences_provider.dart`:

  | Switch | Key | Default |
  |---|---|---|
  | Guia de enquadramento | `capture.frameGuide` | on |
  | Salvar fotos na galeria | `capture.saveToGallery` | off |
  | Registrar localização | `capture.recordLocation` | on |

  - Location defaults to on because recording where a sample was taken is the product's purpose and today's behaviour. The mock's off state is example data, like its names.
  - A store that cannot be read falls back to the default.
- **Guia de enquadramento.** When off, the guided camera (SPEC 0165) draws the camera, the shutter and its two controls, and nothing else:
  - no frame, banner or quality chips;
  - no automatic capture;
  - the shutter is always enabled.

  The photograph is still classified, and a photograph without a readable sheet is still refused by name (ADR 0017). The guide only stops helping; the reader keeps judging.
- **Salvar fotos na galeria.** When on, saving a record also hands the stored photograph to the device gallery through `gal` 2.3.3. It files no album, because an album would need read/write Photos access on iOS and legacy storage on Android 10, while a plain save needs neither (review of #438).
  - The copy is the stored file, which `ImageStorageService` has already stripped of EXIF, so the gallery receives no coordinates.
  - The save is behind a `GallerySaver` interface, so tests replace it.
  - A gallery that refuses the photograph does not undo the record. The screen says "Não foi possível salvar a foto na galeria." once.
  - Android needs no permission from API 29.
    - Android 9 and older would need `WRITE_EXTERNAL_STORAGE`, which SPEC 0165 removes from the merged manifest for the Play Data safety answers (#293). The manifest stays as it is, so on those versions the save fails and the failure line says so.
  - iOS gets `NSPhotoLibraryAddUsageDescription`: "O VisioSoil salva na galeria as fotos das amostras, quando você ativa essa opção."
  - iOS also gets `NSPhotoLibraryUsageDescription`: "O VisioSoil precisa do acesso às fotos para salvar nelas as fotos das amostras, quando você ativa essa opção." iOS 13, the deployment target, asks for read/write access even for a plain save, and a missing description ends the app.
- **Registrar localização.** When off, a capture asks for no location and saves no coordinates. The location state goes straight to `unavailable`, as when the GPS gives up.

## Alternatives Considered

- **Keep the switches disabled.** Rejected by the Developer's request: the mock draws them live.
- **Draw them enabled with nothing behind them.** Rejected: a switch that changes nothing tells the agronomist something false.
- **Save the picker's original file to the gallery.** Rejected: it still carries EXIF, coordinates included, which SPEC 0002 removes on purpose.

## Scope

- Includes:
  - the three preferences, their providers and their restore in `main`;
  - the guided camera's guide-off form;
  - the gallery save after a record is written;
  - the location skip in the capture screen;
  - the three switches in Configurações;
  - `gal` in `pubspec.yaml`, and `NSPhotoLibraryAddUsageDescription` in `ios/Runner/Info.plist`;
  - the provider count in `docs/agents/project.md`, with `CLAUDE.md` regenerated by `mf agents sync`.
- Does NOT include:
  - "Sincronizar só no Wi-Fi", which stays disabled until sync exists (PNG 23 draws it disabled too).
  - The guided camera's restyle to PNG 10 to 12.

## Acceptance Criteria

- `plugin_saver_files_no_album`: `PluginGallerySaver` asks for access and saves with no album.
- `ios_declares_both_photo_descriptions`: the iOS plist declares both Photos usage descriptions.
- `capture_switches_are_live`: Configurações' three switches are enabled and reflect their providers; tapping one flips its provider.
- `capture_preferences_persist`: each controller writes its key, and `restoreCapturePreferences` reads it back, with the defaults above when nothing is stored.
- `guide_off_hides_the_guide`: with the guide off, the guided camera shows no quality chip and no "Captura liberada" line, and its shutter is enabled before any reading.
- `location_off_skips_the_fix`: with location off, a capture never calls the locator and saves a record without coordinates.
- `gallery_on_copies_the_stored_photo`: with the gallery on, saving a record hands the stored path to the `GallerySaver`; with it off, nothing is handed.
- `gallery_failure_keeps_the_record`: a `GallerySaver` that throws leaves the record saved and shows the failure line.
- Existing tests pass.

## Reproducibility

Flutter 3.44.1, Dart 3.12.1. Run `flutter test`, `flutter analyze` and `mf check`.

## Risks and Assumptions

- `gal` adds a native plugin. The release build's R8 pass must keep it, which CI's build and smoke jobs exercise.
- With the guide off, more photographs will be refused by the sheet reader. That is the trade the switch offers, and its subtitle says what it turns off.
