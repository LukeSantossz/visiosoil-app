# SPEC: feat(branding): refine the brand mark's geometry

## Problem

The brand mark's strokes and grains are thin for the sizes it is shown at, since on its 48-unit viewBox the ring stroke is 3.2 units and the smallest grain 2.8 units across while the launcher draws it at 60% of a 48 dp tile, and the Developer chose on 2026-11-04 to keep the current identity and refine the mark (identity direction 1, "Lente e Grão").

## Design Decision

### 1. One geometry change, in one place

`VisioSoilMarkGeometry` in `lib/core/widgets/visio_soil_logo.dart` is the only source of the mark's numbers. The new values, on the same 48-unit viewBox:

| Part | Before | After |
|---|---|---|
| Ring centre | (20, 20) | (20, 20) |
| Ring radius | 13 | 12.6 |
| Ring stroke | 3.2 | 3.6 |
| Grain 1 (largest) | (16.5, 18), r 3.0 | (16.2, 17.6), r 3.2 |
| Grain 2 | (23.5, 19.5), r 2.1 | (23.6, 19.2), r 2.2 |
| Grain 3 (smallest) | (19.5, 24.5), r 1.4 | (19.4, 24.6), r 1.5 |
| Handle | (29.5, 29.5) to (39, 39), stroke 3.4 | (29.4, 29.4) to (39.5, 39.5), stroke 4.0 |

What the numbers do:
- The ring and handle are about 12% and 18% heavier.
- The ring's inner edge stays 3.1 units clear of the largest grain, so the grains still read as held inside the lens.
- The three grains keep their order and their decreasing sizes.
- The mark's bounding box moves by at most 0.8 units on any side (5.6 to 41.5, was 5.4 to 40.7), so it stays centred where it is placed today.

### 2. Everything that draws the mark follows

Everything that draws the mark reads the geometry or is pinned to it, so no layout and no call site changes:
- `paintVisioSoilMark`, the boot animation's `_BootMarkPainter` (SPEC 0217) and `VisioSoilLogo` read `VisioSoilMarkGeometry`, so they change with it.
- `android/app/src/main/res/drawable/launch_mark.xml` is rewritten to the new numbers. `test/android_launch_screen_test.dart` already pins every number in it to the geometry (SPEC 0089).
- The launcher sources are regenerated by the existing local generator, `GENERATE_ICONS=1 flutter test test/tools/generate_app_icon_test.dart` (SPEC 0025):
  - `assets/branding/app_icon.png`;
  - `assets/branding/app_icon_foreground.png`.

  Then the platform icons are regenerated by `dart run flutter_launcher_icons`: the Android mipmaps and adaptive foregrounds, and the iOS `AppIcon.appiconset`.
- The tile stays #4A7C59, the mark stays white on it, and the 60% and 90% mark fractions stay.

### 3. A guard that the committed icons follow the geometry

Today `test/core/branding/app_icon_test.dart` checks only that some white pixel sits in the tile's centre, so an icon drawn from an older geometry still passes. A new test, `committed_icons_follow_the_mark_geometry`, closes that gap:
- It computes, for a grid of pixels in each committed source, the signed distance to the mark drawn from `VisioSoilMarkGeometry` at that source's fraction.
- A pixel at least 2.5 px inside the mark must be white.
- A pixel at least 2.5 px outside it must be the tile:
  - in `app_icon.png`, green #4A7C59;
  - in `app_icon_foreground.png`, transparent.

It reads the PNGs and does not rasterize, so it runs in CI like the existing guard.

### 4. The doc comment

`VisioSoilLogo`'s doc comment says it paints "from the design system's canonical `assets/logo-mark.svg`". That file is not in the repository. The comment will say instead that:
- the geometry was first taken from that file (SPEC 0024) and refined by this spec;
- `VisioSoilMarkGeometry` is now the canonical source.

## Alternatives Considered

- **A separate small cut with two grains for 24 px and below.** The identity mocks proposed it. Not now: nothing in the app draws the mark at 24 px or below today, and a cut with no caller is code ahead of its need. It belongs with the favicon and GitHub avatar work.
- **A two-tone mark on light backgrounds** (ring #1F4D2E, grains #4A7C59). Not now: every place the app draws the mark puts it in white on green. A second colour would change `VisioSoilLogo`'s constructor and `paintVisioSoilMark`'s signature for no screen that uses it.
- **Keep the geometry and change only the launcher icon.** Rejected. The launcher, the native launch window and the boot animation must show one mark, which is why SPEC 0089 pinned them together.
- **Restore `assets/logo-mark.svg`.** Not needed by the app, which paints from code. An SVG export belongs with the external brand pieces.

## Scope

- Includes:
  - the new numbers in `VisioSoilMarkGeometry`;
  - `launch_mark.xml` rewritten to match;
  - the regenerated launcher sources and the platform icons generated from them;
  - the updated expectations in `test/core/widgets/visio_soil_logo_test.dart`;
  - the new guard in `test/core/branding/app_icon_test.dart`;
  - the doc-comment correction.
- Does NOT include:
  - any colour, token, font or theme change;
  - any screen layout, size, spacing, copy or motion timing change;
  - a small cut, a two-tone variant, an SVG export, a favicon, a GitHub avatar, a social preview or Play Store graphics;
  - `site/`, the README, or any document outside this spec.

## Acceptance Criteria

- `paintVisioSoilMark` at 48 units draws the ring, grains and handle with exactly the "After" numbers above, and at 96 units it draws each of them at twice that.
- `android_launch_screen_test.dart` passes with `launch_mark.xml` carrying the new numbers. It fails on the old XML once the geometry changes.
- `committed_icons_follow_the_mark_geometry`:
  - fails against the icons on `main`;
  - passes against the regenerated ones.
- The existing launcher-icon and launch-screen tests pass unchanged, apart from the numbers this spec changes.
- No file under `lib/` other than `visio_soil_logo.dart` changes.
- `flutter analyze` reports no issues.
- `flutter test` shows no failures beyond those this machine has on `main`.
- `mf check` passes.

## Reproducibility

Flutter 3.44.1 / Dart 3.12.1 in CI. Checked locally on Flutter 3.47.7. Regenerate the sources with `GENERATE_ICONS=1 flutter test test/tools/generate_app_icon_test.dart`, then the platform icons with `dart run flutter_launcher_icons`. Then run `flutter test`, `flutter analyze` and `mf check`.

## Risks and Assumptions

- **The local Flutter differs from CI.** The rasterizer that draws the sources is the local engine, 3.47.7, not CI's 3.44.1. The guard samples only pixels at least 2.5 px from any edge, so anti-aliasing differences between engines cannot flip it.
- **`flutter_launcher_icons` rewrites more than the PNGs.** It may also touch `Contents.json` or the adaptive-icon XML. Any change other than the image bytes is reverted or explained in the pull request.
- **Assumption:** the boot animation's timings (SPEC 0217) read well with heavier strokes. Only the stroke widths change, not when each part appears.
