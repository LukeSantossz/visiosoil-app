# ADR 0025: The Dart resample reproduces Pillow's BILINEAR byte for byte

## Status

Accepted 2026-09-29, promoted from
[SPEC 0081](../specs/0081-cut-the-canonical-patch-grid-in-dart-from-a-measured-scale.md)
at the Spec Gate. It reverses the shared-kernel alternative that
[SPEC 0037](../specs/0037-scale-normalised-greyscale-patch-pipeline.md) rejected,
and it supersedes the Dart half of the solution #180 proposed.

## Decision

The resample that takes a photograph to the canonical millimetres per pixel is
Pillow's `BILINEAR`, ported to Dart, and the port matches Pillow to the byte. The
same holds for the steps between the resample and a patch:

- the grey plane, whose BT.601 luma is rounded half to even as numpy's `rint`
  does;
- the patch corners, rounded half to even as Python's `round` does;
- the grid's step count, which is Python's float floor division.

A cross-language golden generated by `ml/src/patches.py` holds the two sides
together, with bytes compared exactly.

The rule is **identical arithmetic, not approximately equal pixels**. It is
achievable because nothing in the chain calls a libm function. Pillow computes
its coefficients with `+`, `−`, `×`, `÷` and `ceil` and accumulates in 22-bit
fixed point, so every step is either IEEE-exact or integer, on any CPU.

## Why the earlier rejection no longer holds

SPEC 0037 rejected a shared resampling kernel as disproportionate "for a
difference nothing has measured", and #180 proposed each language's own box
filter instead. Both were written when a convolutional network read the pixels.
A network was expected to tolerate a small change of low-pass, and that
tolerance was never tested.

[ADR 0024](0024-the-descriptor-path-is-the-v1-classifier-computed-in-dart-from-a-contract-of-numbers.md)
changed what reads the pixels. The spectral bands measure energy at physical
wavelengths, which is exactly what a low-pass filter shapes. LBP and GLCM read
neighbouring grey levels, which are exactly what a resampling kernel mixes. E0's
ablation found that removing LBP costs 15.6 points. The descriptors themselves
are held to Python at `1e-9` (SPEC 0077). A different kernel in front of them
would give that precision back at the first step, where no test could see it.

Rounding is part of the same decision because it moves pixels just as surely.
13,178 RGB triples have a BT.601 luma of exactly .5 in float64. Dart's `round`
sends each of them one grey level away from where numpy's `rint` sends it.

## Considered Options

- **Each language's own box filter** (`Interpolation.average` in Dart), as #180
  proposed. Rejected. Training uses a triangle filter, so every descriptor would
  read a different low-pass than the one the model was fitted on, by an amount
  nobody has measured.
- **A kernel both languages share that is simpler than Pillow's, adopted in
  Python as well.** Rejected. It changes the training input, and the E0 verdict
  and every fold artefact were computed on Pillow's `BILINEAR`.
- **Pixels equal within a tolerance** instead of identical. Rejected as the
  rule, because it can be had for the same price. The arithmetic has no libm
  call, so exactness costs nothing more than care over the order of operations
  and the rounding, and a tolerance would have to be justified by a measurement
  that does not exist.
- **Leaving the kernel to the wiring.** Rejected. The wiring would inherit a
  decision that has to be made before any patch is cut, and no golden would stand
  behind it.

## Consequences

- **The Dart port is written against Pillow's source, not re-derived.** Its
  operation order is the reference's, and the golden is what proves it. The
  version is pinned: `pillow>=10.0.0,<11.0.0` today, and the Python test
  regenerates with the installed Pillow, so a version that changed the resample
  fails rather than drifts.
- **Python's rounding becomes a Dart helper.** A Dart `round` in this path is a
  defect, not a style choice.
- **Exactness depends on staying off libm.** A future step that needs `exp`,
  `log`, `pow` or trigonometry breaks this rule. For that step, a golden compared
  within a tolerance is the honest form, as
  [SPEC 0080](../specs/0080-compare-the-regenerated-descriptor-golden-within-tolerance.md)
  found for `np.geomspace`.
- **The rule stops at the resample, and two gaps are left open.** Dart's JPEG
  decoder and Pillow's can disagree before the resample. And the sheet reader's
  perspective warp is a second resample that the dataset side does not have.
  Both are named in SPEC 0081's risks rather than covered by this record.

## What would reopen it

- **The port proving unable to match**, for example because the Dart VM contracts
  a multiply-add that Pillow's build does not. The rule would then fall back to a
  tolerance, with the measured difference recorded.
- **The resample proving too slow on the reference device** (A7). A faster
  kernel would then have to be adopted on both sides at once, with the training
  arms re-run.
